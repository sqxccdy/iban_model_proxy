## 2. 关于“根据返回的数组整理，新写指标代码”的理解

新指标需要新增采集和汇总代码，不是把原来只有 token 总量的数字换个名称。当前已开始写新的用量提取、每日聚合、指标计算和展示逻辑。

token 的数据来源是上游实际返回的用量字段。当前新代码先兼容原项目使用的 JSON/SSE 返回格式：

| 指标 | 当前使用的数据及计算方式 |
| --- | --- |
| 输入 token | Chat/Embeddings 的 `usage.prompt_tokens`，或 Responses 的 `usage.input_tokens`。 |
| 输出 token | Chat 的 `usage.completion_tokens`，或 Responses 的 `usage.output_tokens`。 |
| 总 token | 优先读取 `usage.total_tokens`；缺少总数字段时使用已取得的输入与输出之和。 |
| 流式 token | 解析返回事件，从最终可取得的 usage 提取数字；兼容嵌套 `response.usage`，不把累计 usage 逐段重复相加。 |
| 每日 token | 将一次调用取得的 token 值累加到对应日期、环境和项目。 |
| 调用次数 | 代理每完成一条调用累计一次，即成功次数加失败次数。不是用返回数组的元素个数计算。 |
| 成功率 | 成功次数 ÷ 调用次数 × 100%；零调用显示“—”。 |
| 平均响应时长 | 所有已记录调用的耗时总和 ÷ 调用次数；包含成功和失败，流式请求计算整段流完成时间。不是首 token 时间。 |

如果用户所说的“返回数组”是某个上游特有的数组结构，**目前还没有具体数组字段样本，尚未完成针对该结构的适配**。下次应先对照真实返回数据确认字段，再补充提取代码。不能用响应文本长度或数组长度猜测 token。

次数、成功率和耗时需要代理自身记录调用结果与起止时间；通常不能只从上游的 token 数组得到这几个值。

### `src/key_registry.py`：新增环境与项目配置模块

- 从入口文件拆出 Authorization 规范化、密钥摘要、环境映射查询等函数。

- 当前已写的规则：环境密钥和项目密钥不能混用；有项目的环境不能直接删除；同一项目密钥不能改绑其他环境，避免历史数据的归属与现有配置错位。项目可改名，换环境需使用新项目密钥。

新增 Redis 配置键：

- `monitor:project:mappings`：项目配置 JSON。
- `monitor:project:owners`：项目密钥对应的环境归属记录，删除项目配置后仍保留，用于避免旧密钥被改绑导致历史混淆。
